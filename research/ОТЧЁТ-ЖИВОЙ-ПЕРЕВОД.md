# Исследование: «говорю по-русски — слышу себя на испанском вживую»

Дата: 11.11.2026 · Машина: RTX 5080 (16 ГБ VRAM), 31 ГБ RAM, 16 ядер

## Цель

Говорю по-русски → нажимаю кнопку → **все слышат меня на испанском моим же
голосом**, и это работает одинаково в Discord, в игре и где угодно ещё.

## Вывод в одном абзаце

Технически **реализуемо на этой машине полностью локально**, без облака и без
интернета. Измеренная задержка от конца фразы до первого звука на испанском —
**~520–800 мс**, то есть человек начинает слышать перевод раньше, чем договорит.
Голос остаётся твоим: клонирование делает XTTS-v2 на твоём образце.
Единственное, чего не хватает системе, — **виртуального аудиокабеля**, чтобы
испанское звучание попадало в микрофон Discord/игры вместо твоей русской речи.

## Измеренные цифры (не оценки, а прогоны)

Всё замерено на твоих же записях из `workspace\voice_samples`.

| Этап | Модель | Задержка |
|---|---|---|
| Распознавание речи (RU) | faster-whisper large-v3-turbo, GPU | **130–150 мс** (RTF 0.04) |
| Перевод RU→ES | opus-mt-ru-es **локально**, GPU | **33–70 мс** (медиана 78) |
| Синтез (ES, твой голос) | XTTS-v2 `inference_stream`, GPU | **340–420 мс до первого звука** |
| **ИТОГО до первого звука** | | **~520–800 мс** |

Дополнительно:

- загрузка XTTS-модели: 8.5 с (один раз при старте)
- кэш голоса (`conditioning latents`): 1.37 с в первый раз, **0.03 с** дальше
  → голос считается один раз и переиспользуется
- RTF XTTS потокового: 0.40–0.55 (говорит быстрее, чем в реальности)

### Ключевое открытие: локальный перевод вместо сетевого

Приложение сейчас переводит через **Google endpoint** — это давало **1768 мс**
(среднее), то есть было главным узким местом.

Локальная модель `Helsinki-NLP/opus-mt-ru-es` (Apache-2.0, 309 МБ) на той же
GPU даёт **118 мс** — в **15 раз быстрее** и работает без интернета.

| Перевод | Среднее | Медиана | Максимум |
|---|---|---|---|
| Сетевой (Google) | 1768 мс | 1569 мс | 3454 мс |
| **Локальный (opus-mt, GPU)** | **118 мс** | **78 мс** | 402 мс |

Итог по конвейеру: **2318 мс → 809 мс**.

## Главное препятствие: маршрутизация в микрофон

Чтобы «все услышали», испанское должно звучать **из микрофона** того приложения,
в котором ты находишься (Discord, RedM). Три варианта:

### Вариант A. Виртуальный аудиокабель (рекомендую)

Ставится один раз: **VB-CABLE** (бесплатный) или **VoiceMeeter**.

Схема:

```
ты говоришь по-русски
   → Whisper (RU)
   → opus-mt (RU→ES)
   → XTTS (ES, твой голос)
   → вывод в «CABLE Input»
   → «CABLE Output» выбран микрофоном в Discord/игре
   → все слышат испанское твоим голосом
```

- Плюс: работает **везде** одинаково — Discord, RedM, любая программа
- Плюс: твой настоящий микрофон можно оставить подключённым (кнопка Push-to-Talk)
- Минус: нужно установить одну программу (≈10 МБ, один раз)

### Вариант B. Без установки: «Стерео микшер» + вывод в наушники

«Стерео микшер (Realtek USB Audio)» уже есть в системе (idx 31) и работает
на 44100 Гц. Схема: XTTS → обычный выход → «Стерео микшер» → микрофон.

- Плюс: ничего ставить не нужно
- Минус: **RedM его не показывает в списке микрофонов** (проверено ранее),
  то есть в игре не сработает. В Discord, скорее всего, сработает.
- Минус: в наушниках «Стерео микшер» ловит только то, что играется в динамики,
  а не в наушники — придётся переключать вывод на динамики

### Вариант C. Серверный ресурс RedM (уже сделано в проекте)

Для RP-сервера: фразы играет сервер, их слышат все игроки рядом. Уже собрано в
`workspace\server_resource`.

- Плюс: работает в игре без микрофона вообще, качество идеальное
- Минус: это **заранее записанные фразы**, а не живой перевод; в Discord не подходит

## Почему «нажал кнопку» — правильная модель

Живой непрерывный перевод (говорю и слышу себя через 300 мс) — это уже не
«озвучка», а полноценный голосовой чат: нужен стриминговый ASR с частичными
результатами, инкрементальный перевод и очередь синтеза. Реализуемо, но сложнее.

**Push-to-talk (зажать кнопку → сказать → отпустить → слышно испанское)** —
это ровно то, что ты описал, и оно технически закрыто измеренными цифрами.

## Рекомендуемая архитектура

Новая вкладка в Auraloom — **«Живой перевод»**:

```
[Зажать] -> запись с микрофона (кнопка или горячая клавиша)
         -> Whisper large-v3-turbo (GPU, 16 кГц)
         -> opus-mt-ru-es (GPU)
         -> XTTS-v2 inference_stream (твой голос, ES)
         -> немедленный вывод в виртуальный кабель
[Отпустить]
```

Обязательные условия:

1. **Батчинг**: не ждать конца фразы. Резать по паузам (VAD) и синтезировать
   каждую фразу отдельно — тогда задержка не растёт с длиной речи.
2. **Кэш голоса**: `get_conditioning_latents` один раз при старте (1.37 с),
   дальше 0.03 с.
3. **Потоковый вывод**: `inference_stream` даёт первый звук за 350 мс, а не
   ждёт конца всей фразы.
4. **Перевод локальный**: opus-mt, не сеть.
5. **Отмена по Escape/кнопке** — прервать на полуслове.

## Чего НЕ нужно делать

- Не нужен облачный TTS (всё работает локально, голос не уходит наружу)
- Не нужен CosyVoice3 / F5-TTS / GPT-SoVITS — XTTS-v2 уже стоит, умеет
  стримить и клонирует; CosyVoice требует conda и Linux-пакеты
- Не нужно переобучать модель на твоём голосе
- Не нужен «серверный» подход для Discord — только виртуальный кабель

## Альтернативы, если XTTS покажется слабым по качеству

| Модель | Плюсы | Минусы |
|---|---|---|
| **XTTS-v2** (сейчас) | уже стоит, стриминг, клон | качество «среднее+» |
| CosyVoice3-0.5B | 150 мс, RU+ES, лучше сходство | conda + Linux-зависимости, 0.5B, лицензия |
| F5-TTS | очень быстро, zero-shot | нет RU-фронтенда в стандарте |
| GPT-SoVITS v4/v5 | RTF 0.014, отличный клон | надо обучать на 1+ мин голоса, китайский фронтенд |

Проверять стоит только если XTTS не устроит по качеству — это отдельная
задача на полдня.

## Открытые вопросы к тебе

1. **Ставить VB-CABLE?** Это единственное, что нужно для «работает везде».
   Один раз, ≈10 МБ. Без него в Discord возможно, в игре — нет.
2. **Push-to-talk или непрерывный?** Push-to-talk проще и надёжнее; непрерывный
   требует существенно больше работы.
3. **Перевод — только текстом или с сохранением интонации?** Текущий конвейер
   переводит текст, поэтому интонация «нейтральная». Если нужна эмоция — есть
   варианты, но это отдельная работа.

## Назначение проекта

Auraloom — локальное приложение для RP-сервера RedZ (RedM/FiveM):

1. **Звуковая панель** — 31 реплика с мексиканским акцентом, озвученные голосом
   пользователя, доставка в игру (ресурс сервера / виртуальный кабель / плеер).
2. **Живой перевод** — «говоришь по-русски → собеседник слышит твой голос на
   испанском»: Whisper (ASR) → opus-mt (перевод) → XTTS-v2 (синтез твоим голосом).
3. **Voice Studio** — запись образца голоса, клонирование, профили, проверки
   качества, озвучка текстов.

Всё работает локально, без облака и без интернета (после установки моделей).

## Кратко об архитектуре

```
PySide6 + QML (GUI, app/qtapp)  ──►  app/*.py (ядро, аудио, хоткеи, пути)
        │                                     │
        │ JSON-lines через stdin/stdout        │ subprocess
        ▼                                     ▼
  LiveEngine (Qt-объект)  ──────────►  engine/python.exe tools/live_translate.py
                                        faster-whisper + opus-mt + XTTS-v2
```

Тяжёлый стек (torch + coqui-tts) в EXE **не входит**, живёт отдельно в
`%LOCALAPPDATA%\Auraloom\engine`. Подробности — [ARCHITECTURE.md](ARCHITECTURE.md).

## Карта проекта

```
redz_mx_soundboard/
├── app/                     # исходники приложения
│   ├── voice_studio.py      # точка входа: --ui-old (Tk старый), --ui-new, --ui-qt (по умолчанию)
│   ├── qtapp/               # новый интерфейс: PySide6 + QML
│   │   ├── main.py          # сборка QML-движка, контекст, история, автозапуск
│   │   ├── app_state.py     # состояние UI ↔ ядро (устройства, настройки, движок, фразы)
│   │   ├── live_engine.py   # живой перевод: PTT, непрерывный режим, уровень, состояние
│   │   ├── voice_controller.py # запись образца, дубли, сравнение
│   │   ├── models.py        # модели QML: подсказки, дубли, семплы, история
│   │   └── qml/             # main.qml, pages/*.qml, RedZ/ (дизайн-система), icons/
│   ├── studio_core.py       # Recorder, reference, запуск движка, раскладка файлов
│   ├── studio_paths.py      # workspace, engine, профили, сидинг, single-instance lock
│   ├── live_client.py       # клиент движка (subprocess + JSON-lines IPC)
│   ├── mic_bridge.py        # мост: микрофон + фразы + TTS → одно устройство
│   ├── wasapi_loopback.py   # захват системного звука (собеседники)
│   ├── incoming_tts.py      # озвучка входящего перевода в наушники
│   ├── cable.py             # VB-CABLE: поиск, установка, устройства

│   ├── translate.py         # текстовый перевод (fallback)
│   ├── ui/                  # Legacy Tk-интерфейс (3 и 6 вкладок)
│   └── redz_voice_studio.spec  # PyInstaller onefile
├── tools/                   # CLI: движок перевода, озвучка, проверки, сборка
├── tests/                   # unittest (127 тестов)
├── voices/ player/ html/ sounds/ out/   # ресурсы озвучки и плеера
├── lines.json               # 33 фразы: es/ru/en/ow/it, категории, клавиши
```

## Обязательный процесс разработки

```
READ DOCS → VERIFY REALITY → ONE CONTROLLED CHANGE → TEST → DOCUMENT → GIT CHECKPOINT
```

1. **READ DOCS** — прочитать этот каталог и нужный раздел README.
2. **VERIFY REALITY** — проверить код и запуск, не верить старой документации.
3. **ONE CONTROLLED CHANGE** — одно законченное изменение за раз.
4. **TEST** — статическая проверка + целевой запуск (см. TEST_PLAN).
5. **DOCUMENT** — обновить FEATURE_PARITY / CHANGELOG.
6. **GIT CHECKPOINT** — отдельный осмысленный коммит.

## Статусы

| Статус | Значение |
|---|---|
| `PASS` | проверено и работает (есть лог/тест/воспроизводимый сценарий) |
| `FAIL` | обнаружена неисправность, воспроизведена |
| `UNVERIFIED` | код есть, но работоспособность не проверена |
| `BLOCKED` | проверка невозможна из-за внешнего ограничения (нет устройства, прав, сети) |
| `IN PROGRESS` | работа выполняется |
| `NOT READY` | критерии завершения не выполнены |

Статическая проверка (импорты, линт, чтение кода) **не** даёт `PASS` для
runtime-функции.

## Правила безопасной работы с Git

- Ветка `main` защищена процессом: изменения идут через отдельные ветки.
- Запрещено: `git reset --hard`, `git clean -fd`, `git push --force`,
  принудительное переключение веток, удаление пользовательских файлов.
- Незакоммиченные изменения пользователя не перезаписываются и не откатываются.
- Документационные коммиты содержат только документы.
- Слияние в `main` — только с явного разрешения пользователя.

## Требования к тестированию

Минимум перед коммитом: `python -m compileall app`, `python -m unittest discover -s tests -q`,
`pyside6-qmllint -I app/qtapp/qml <qml>`. Для UI-изменений — визуальная проверка
и проверка запуска (`app/qtapp/test_launch.py`). Для интеграционных изменений —
проверка цепочки «действие → UI → Engine → ответ → отображение».

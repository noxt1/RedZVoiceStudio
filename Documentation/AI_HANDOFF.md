## A. PRODUCT OVERVIEW

**Auraloom** — локальное Windows-приложение для игрока RP-сервера (RedM /
FiveM), три функции в одном продукте:

1. **Звуковая панель** — 33 заранее озвученные реплики (испанский с
   мексиканским акцентом), озвученные голосом пользователя, с доставкой в
   голосовой канал игры: серверный ресурс, виртуальный кабель (мост) или
   локальный HTML-плеер.
2. **Живой перевод** — «говоришь по-русски → собеседник слышит твой голос на
   испанском/английском/итальянском»: ASR → перевод → синтез клоном голоса,
   всё локально, без облака.
3. **Voice Studio** — запись образца голоса по подсказкам, сборка reference,
   профили, клонирование XTTS-v2, проверки качества.

Отдельно реализован **обратный канал**: приложение снимает звук игры/системы,
распознаёт речь собеседников, переводит её на русский, показывает в оверлее и
озвучивает в наушники.

Название продукта — Auraloom. `RedM`, `FiveM` и `RedZ` (RP-сообщество, под
чьи правила подбирались реплики) — внешние имена, они не переименовываются.

## C. PRODUCT ARCHITECTURE

```
┌──────────────────────── GUI (Python 3.14, PySide6 6.12 + QML) ────────────┐
│  app/qtapp/qml/main.qml ─ Loader ─ pages/{Home,Live,Voices,Models,        │
│                                    Phrases,History,Settings}.qml         │
│  дизайн-система: qml/Auraloom/ (Theme, Card, Glow, AppButton, AppCombo,   │
│                  AppField, AppSlider, AppSwitch, SideNav, MicOrb, …)      │
│  контекст QML: appState, liveEngine, voiceController, promptModel,        │
│                takeModel, sampleModel, historyModel                       │
└───────────────┬───────────────────────────────┬───────────────────────────┘
                │ слоты/свойства                 │ сигналы (notify)
                ▼                                ▼
     AppState (app_state.py)            LiveEngine (live_engine.py)
     настройки, устройства, фразы,      PTT, непрерывный режим, уровень,
     VRAM, хоткеи, мост, профили        очередь фраз, состояние движка
                │                                │
                │                    LiveTranslator (live_client.py)
                │                                │ JSON-lines: stdin/stdout
                ▼                                ▼
     app/*.py: studio_paths, studio_core,     engine\Scripts\python.exe
     mic_bridge, cable, hotkeys, translate,   tools/live_translate.py
     wasapi_loopback, incoming_tts, audiodev  faster-whisper + opus-mt + XTTS
```

Слои:

| Слой | Модули | Ответственность |
|---|---|---|
| UI | `app/qtapp/qml/**` | отрисовка, ввод, навигация; бизнес-логики нет |
| Мост в QML | `app/qtapp/app_state.py`, `live_engine.py`, `voice_controller.py`, `models.py` | свойства/слоты/сигналы, состояния |
| Ядро | `studio_core.py`, `studio_paths.py`, `prompt_library.py`, `voice_prompts.py` | запись, reference, раскладка файлов, профили |
| Аудио | `mic_bridge.py`, `wasapi_loopback.py`, `incoming_tts.py`, `cable.py`, `audiodev.py`, `acoustic.py` | устройства, маршрутизация, захват, установка кабеля |
| Интеграции | `live_client.py`, `translate.py`, `hotkeys.py` | IPC движка, текстовый перевод, глобальные клавиши |
| Legacy | `voice_studio.py`, `live_tab.py`, `ui/**` | старый Tk-интерфейс, запуск `--ui-old` |
| Брендинг | `branding.py` | имя продукта, папка данных, версия |

Ключевые решения:

- **IPC** — построчный JSON через stdin/stdout процесса движка. Поколение
  процесса (`_proc_gen`) отбрасывает хвост вывода старого движка.
- **Очереди** — входящая ограничена 8 (вытесняются промежуточные срезы),
  исходящая 3 (старая фраза вытесняется). Счётчики `dropped`/`cancelled`.
- **Модели по требованию** — `load` / `unload`; перевод выбирается языком, а
  не режимом; режим Fast/Balanced/Quality меняет только параметры уже
  установленных моделей и ничего не скачивает.
- **Ошибки** — состояние `ERROR` + тост; EOF процесса → «движок остановился»;
  перезапуск разрешён и проверен.

Подробная схема IPC, режимы и потоки — `ARCHITECTURE.md`.

## D. IMPLEMENTED FEATURES

Реализовано в коде (не обязательно проверено — см. E/F):

**Движок и перевод**
- загрузка/выгрузка моделей, состояния `STOPPED/LOADING/READY/STOPPING/ERROR`;
- ASR: faster-whisper, модель выбирается из установленных;
- перевод: opus-mt, направления RU→ES/EN, ES→RU, EN→RU, IT→RU (через
  `it→en`), «олдвест» — стилизация английского словарём;
- синтез XTTS-v2 с клоном голоса, потоковые чанки, живость 0–3, тон по смыслу
  русской фразы, расстановка пауз и знаков препинания;
- очереди, поколения (`Engine.gen`), кэш цепочек перевода, дедупликация фраз,
  backpressure при переполнении, метрики и `diagnostics.log`;
- частичное распознавание (`peer_partial` показывается, но не переводится);
- обратный канал: loopback → VAD-нарезка → ASR → перевод на русский →
  озвучка в наушники (отдельная шина, не в кабель).

**Аудио**
- выбор устройств входа/выхода, автоподбор частоты (`audiodev.py`);
- мост `MicBridge`: микрофон + фразы + синтез в одно устройство, ducking на
  время перевода, защита от самозахвата (feedback gate), монитор в наушники;
- VB-CABLE: поиск, скачивание установщика с зеркал, установка, устройства;
- WASAPI loopback для речи собеседников; индикатор уровня микрофона.

**Voice Studio**
- 18 подсказок, запись дублей, выбор лучшего, сборка reference (до 45 с);
- профили голоса, переключение на лету, сравнение с образцом (ECAPA + F0 +
  спектр), прослушивание;
- клонирование через `tools/xtts_clone.py`, авто-починка повторов, подбор
  формулировок, `voice_post`/`voice_tone` (паузы, знаки, живость).

**Model Manager**
- каталог моделей и языковых пакетов, установка/удаление/проверка целостности,
  выбор ASR/TTS, прогресс и отмена загрузки, ручной запуск и остановка
  моделей с выгрузкой из RAM/VRAM.

**Остальное**
- история переводов (3 дня), банк фраз (33 + свои), настройки в
  `ui_settings.json`, диагностика, глобальные хоткеи (включая одиночные
  клавиши и подбор свободной), оверлей субтитров поверх игры, сборка
  серверного ресурса для RedM, массовая озвучка и проверки качества (CLI),
  экспорт/архив, single-instance lock.

## G. MODELS AND HARDWARE

**Модели (реально используются)**

| Роль | Модель | Заметки |
|---|---|---|
| ASR | `mobiuslabsgmbh/faster-whisper-large-v3-turbo` | `int8_float16`, VRAM ~1019 МБ; fallback `Systran/faster-whisper-small` |
| ASR (экономия) | faster-whisper small | 0.17 с против 0.78 с, но теряет слова и пунктуацию |
| Перевод RU→ES | `Helsinki-NLP/opus-mt-ru-es` | CPU, ~309 МБ, 33–70 мс |
| Перевод RU→EN | `Helsinki-NLP/opus-mt-ru-en` | CPU |
| Перевод ES→RU | `Helsinki-NLP/opus-mt-es-ru` | ~594 МБ, проверен сквозным прогоном |
| Перевод EN→RU | `Helsinki-NLP/opus-mt-en-ru` | установлен |
| Перевод IT→RU | `Helsinki-NLP/opus-mt-it-en` + `en-ru` | цепочка через английский |
| Синтез | XTTS-v2 (coqui-tts) | клон голоса, CPML — не для коммерции |
| Резервный синтез | Piper es_MX (`ald`, `claude`) | офлайн, без GPU, без клонирования |

Переопределение моделей — переменные окружения `AURALOOM_*`
(например `AURALOOM_ASR_MODEL`, `AURALOOM_MT_DEVICE`, `AURALOOM_STREAM_CHUNK`).
Прежний префикс `REDZ_*` больше не читается.

**Железо, на котором сняты замеры**

RTX 5080 16 ГБ, 31 ГБ RAM, 16 ядер. VRAM под движок ~4.5 ГБ (основной
потребитель — XTTS), GPU при синтезе 54–67 %, загрузка моделей ~19–23 с.

Минимум для работы без GPU: звуковая панель на Piper, банк фраз, история,
экран настроек. Клонирование и живой перевод требуют GPU (иначе задержка
неприемлема).

## I. AUDIO ROUTING

```
микрофон ─┬─► ASR (PTT / непрерывно) ─► перевод ─► XTTS ─┐
          │                                              │
          └─────────────► MicBridge (микшер) ◄───────────┘
                                 │  ducking: микрофон гасится,
                                 │  пока играет перевод
                                 ▼
                    «CABLE Input» (VB-CABLE)
                                 │
                                 ▼
                    «CABLE Output» ──► микрофон в Discord / RedM

звук игры ──► WASAPI loopback ──► ASR ──► перевод на RU ──┬─► оверлей (текст)
                                                          └─► наушники (озвучка)

фразы панели ──► MicBridge или прямое устройство вывода
```

Правила, которые нельзя нарушать:

- перевод **не** играет в колонки/наушники по умолчанию — только в кабель,
  иначе собеседник его не услышит;
- без моста в кабель идёт только перевод: собственная речь пользователя
  теряется (проверено);
- входящая озвучка идёт отдельной шиной в наушники и не попадает в кабель;
- на время своей озвучки loopback-захват закрывается, иначе приложение
  слышит само себя.

## K. KNOWN ISSUES

Технический долг и подтверждённые ограничения:

1. **Discord не настраивается автоматически.** Автоматика (RPC, PKCE,
   keepalive, переключение микрофона) удалена 2026-11-22 как нерабочая на
   живом клиенте. Вместо неё — окно-инструкция: микрофон «CABLE Output»,
   «Изоляция голоса» → «Студия», шумодав/эхо/автогромкость выключить.
2. **USB-гарнитуры без loopback.** Windows не отдаёт петлю для таких
   устройств, перехват речи игры возможен только через «Стерео микшер» или
   кабель.
3. **Клиппинг на выходе.** `_emit_chunk` жёстко клипует в int16; пики
   упираются в 0 dBFS, AGC Discord из-за этого откручивает усиление.
4. **Нет `WARMING UP`** как отдельного состояния — только `LOADING`.
5. **Нет управления темпом/тоном** из UI (только «живость» 0–3).
6. **Qt-UI не покрывает CLI-сценарии**: массовая озвучка, сборка серверного

## P. BRAND MIGRATION

Ребрендинг выполнен целиком в одном коммите 2026-11-24. Правило: заменялся
бренд **продукта**; внешние имена (RedM, FiveM, RP-сообщество RedZ) и
идентификаторы, от которых зависит чужая установка, не тронуты.

**Что переименовано**

| Объект | Было | Стало |
|---|---|---|
| Название продукта | RedZ Voice Studio | Auraloom |
| EXE | `dist/RedZVoiceStudio.exe` | `dist/Auraloom.exe` |
| PyInstaller spec | `app/redz_voice_studio*.spec` | `app/auraloom*.spec`, `app/auraloom_qa.spec`, `app/auraloom_legacy.spec`, `app/auraloom_ui_preview_qa.spec` |
| QML-модуль | `qml/RedZ` (`module RedZ`) | `qml/Auraloom` (`module Auraloom`) |
| Импорты QML | `import RedZ 1.0` | `import Auraloom 1.0` (43 файла) |
| Название приложения | `APP_NAME = "RedZVoiceStudio"` | `"Auraloom"` (в `branding.py`) |
| Папка данных | `%LOCALAPPDATA%\RedZVoiceStudio` | `%LOCALAPPDATA%\Auraloom` |
| Переменные окружения | `REDZ_*` | `AURALOOM_*` |
| Класс окна оверлея | `RedZOverlayWin` | `AuraloomOverlayWin` |
| ttk-стили | `Redz.Horizontal.TProgressbar` | `Auraloom.Horizontal.TProgressbar` |
| Прототип UI | `RedZVoiceStudio_UI_Prototype.zip` | `Auraloom_UI_Prototype.zip` |
| Заголовки окон, сплэш, подписи, тексты установщика | RedZ … | Auraloom … |
| Документация (README, Documentation/*, AUDIT, TESTING) | RedZ | Auraloom |

**Совместимость пользовательских данных**

`app/studio_paths.local_app_data()` → `_migrate_data_dir()`:

1. если `%LOCALAPPDATA%\Auraloom` уже есть — используется она;
2. иначе ищется `LEGACY_DATA_DIRS = ("RedZVoiceStudio",)` и **переименовывается**
   (`os.replace`, атомарно в пределах тома);
3. если переименование не удалось (файлы заняты запущенным движком) —
   работа продолжается в старой папке, чтобы не потерять workspace, движок и
   профили;
4. исходные файлы не удаляются; формат пользовательских файлов не менялся.

Проверено: `%LOCALAPPDATA%\Auraloom` существует и используется приложением
(движок, workspace, профили на месте после перехода).

**Что намеренно оставлено со старым именем (и почему)**

| Место | Причина |
|---|---|
| `branding.LEGACY_DATA_DIRS = ("RedZVoiceStudio",)` | единственный способ найти и перенести данные существующей установки |
| Имя папки-ресурса `redz_mx_soundboard` (README, `fxmanifest.lua`, подсказки в `voice_studio.py`) | имя ресурса в `server.cfg` у тех, кто уже установил его на сервер; вопрос к владельцу (O.2) |
| Путь хранилища Obsidian `…\10-Проекты\RedZ-Voice-Studio` (`tools/check_vault.py`, `tools/link_vault_index.py`, `Documentation/README.md`, `TEST_PLAN.md`) | внешняя папка на диске владельца, не часть продукта |
| «RP-сервер RedZ», «правила RedZ», «RedZ RolePlay», «администрация RedZ» | имя игрового сообщества, под чьи правила подбирались реплики |
| `Documentation/MANUAL_RESULTS.md` — историческая сноска | сохранение прежних результатов тестирования без переписывания фактов |
| История git (`git log`, старые коммиты) | не переписывается по правилам проекта |

Итоговый скан: **0** упоминаний бренда продукта вне перечисленных выше
исключений; в именах файлов и каталогов репозитория — **0**.
